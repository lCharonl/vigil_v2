# Vigil V2

Real-time phishing detection from the Certificate Transparency feed (CertStream).
Modular asynchronous Python MVP, built as an event-driven producer-consumer architecture.

Heuristics are hard-coded in Python and kept separate from network ingestion. The heuristic functions ship **empty** (`return 0, ""`): they are yours to implement (see [ADDING_HEURISTICS.md](ADDING_HEURISTICS.md)).

## Architecture

```
CertStream (WebSocket)
        │
        ▼
┌───────────────────┐   CertEvent   ┌──────────────┐
│ ingestion         │──────────────▶│ core         │
│ certstream_ws.py  │   publish()   │ QueueManager │
└───────────────────┘               └──────┬───────┘
                                           │ get()
                                           ▼
                          ┌─────────────────────────────────┐
                          │ engine                          │
                          │ domain_parser → rules_* → scorer│
                          └────────────────┬────────────────┘
                                           │ ScoreResult (score ≥ threshold)
                                           ▼
                          ┌─────────────────────────────────┐
                          │ output                          │
                          │ formatter (JSON) → dispatcher   │
                          └─────────────────────────────────┘
```

A detailed diagram is available in [doc/vigil_architecture.excalidraw](doc/vigil_architecture.excalidraw).

```
vigil_v2/
├── main.py
└── src/
    ├── core/queue_manager.py        CertEvent + bounded asyncio queue
    ├── ingestion/certstream_ws.py   WebSocket, JSON cleaning, publishing
    ├── engine/
    │   ├── domain_parser.py         FQDN → root / subdomains / TLD (tldextract)
    │   ├── rules_brand.py           Brand heuristics (allowlist, typosquatting)
    │   ├── rules_context.py         Contextual heuristics (keywords, TLD, CA)
    │   └── scorer.py                Orchestrator, accumulates points
    └── output/
        ├── formatter.py             Alert → JSON
        └── dispatcher.py            Terminal and/or JSON Lines file
```

| Module | Role |
|---|---|
| `QueueManager` | Wraps a bounded `asyncio.Queue`. `publish()` never blocks: if the queue is full, the event is dropped and counted in `dropped`. |
| `CertstreamClient` | Connects to the WebSocket, reconnects automatically, ignores CA certificates, strips `*.`, deduplicates, publishes one `CertEvent` per domain. |
| `DomainParser` | Returns a `ParsedDomain` (`fqdn`, `subdomain`, `root`, `suffix`). Uses the suffix list bundled with `tldextract`, with no network access. |
| Data | `src/data/brands_legits_domain.yaml` (brands and official domains) is loaded once by `rules_brand.py` (`check_brand_in_subdomain` heuristic). `src/data/brands_typosquats.yaml`, generated by `scripts/generate_typosquats.py`, feeds `check_typosquatting`. |
| `Scorer` | Applies every rule of the registry, sums the points, collects the reasons. A rule that raises an exception is skipped and logged. |
| `AlertFormatter` / `AlertDispatcher` | JSON serialization, then writing to stdout and/or a file (JSON Lines). |

## Execution model

A single `asyncio` loop, started by `main.py`, hosts concurrent tasks:

1. **ingestion** (producer): reads the WebSocket and publishes to the queue.
2. **engine-N** (consumers, `--workers`): take an event, score it and, if `score >= threshold`, format then dispatch the alert.
3. **stats**: periodically logs the queue size and the number of dropped events.

The bounded queue provides backpressure: the CertStream feed can exceed the analysis capacity, and reading the socket is never blocked. Rules are synchronous and meant to be fast (light CPU, no I/O). A rule that needs I/O should be handled separately. File writes are delegated to a thread.

## Requirements

- Python 3.10 or higher
- A compatible CertStream server ("lite" format: `message_type`, `data.leaf_cert.all_domains`, etc.), for example a local instance of [certstream-server-go](https://github.com/d-Rickyy-b/certstream-server-go)
- Dependencies: `websockets`, `tldextract`, `PyYAML`

## Installation and usage

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python main.py --url ws://localhost:8080/ --threshold 50 --output-file alerts.jsonl
```

| Option | Default | Description |
|---|---|---|
| `--url` | `$CERTSTREAM_URL` or `ws://localhost:8080/` | CertStream server |
| `--threshold` | `50` | Minimum score to raise an alert |
| `--output-file` | none | JSON Lines file, in addition to the terminal |
| `--archive` | disabled | Enables archiving (hourly rotation, daily zip, purge) |
| `--archive-dir` | `archive` | Archive root directory |
| `--archive-retention-days` | `30` | Number of days of zips to keep |
| `--queue-size` | `10000` | Queue capacity |
| `--workers` | `1` | Number of engine consumers |
| `--stats-interval` | `60` | Statistics log period (s) |
| `--verbose` | disabled | DEBUG logs |

As long as the heuristics are empty, every score is 0 and no alert is raised (except with `--threshold 0`, handy to test the pipeline end to end).

## Docker

```bash
docker compose up -d --build
docker compose logs -f vigil
```

`docker-compose.yml` starts two services: `certstream` (certstream-server-go) and `vigil`, which connects to it through `CERTSTREAM_URL=ws://certstream:8080/`. Alerts (`alerts.jsonl`) and the archive (`archive/`) are written to the `vigil-data` volume, mounted on `/data`. The threshold and the number of workers are set with `VIGIL_THRESHOLD` and `VIGIL_WORKERS`:

```bash
VIGIL_THRESHOLD=0 docker compose up -d
docker compose exec vigil tail -f /data/alerts.jsonl
```

To use an existing CertStream server, run only the image: `docker build -t vigil . && docker run --rm -v vigil-data:/data vigil --url ws://host:8080/ --output-file /data/alerts.jsonl`.

## Alert format

```json
{"timestamp": "2026-10-30T11:00:00+00:00", "domain": "login.paypa1-secure.xyz", "root": "paypa1-secure", "subdomain": "login", "tld": "xyz", "score": 80, "reasons": ["typosquatting: paypal"], "issuer": "Let's Encrypt", "serial": "04AB...", "cert_type": "X509"}
```

## Archiving

With `--archive`, each alert is also appended to an hourly file (UTC time):

```
archive/
├── 2026-11-13/            current day
│   ├── 14.jsonl
│   └── 15.jsonl
├── 2026-11-12.zip         finished day: one HH.jsonl per entry
└── 2026-11-11.zip
```

- Once a day is over, its folder is compressed into `YYYY-MM-DD.zip` and then deleted.
- Zips older than `--archive-retention-days` (30 by default) are deleted.
- Maintenance (zip and purge) runs at startup, which catches up on days left as folders after a shutdown, then every hour.
- Independent of `--output-file`: both can be used together. Without `--archive`, nothing is created.

## Code conventions

- No `#` comments in the code body; documentation through docstrings only.
- A heuristic always returns a `(score, reason)` tuple.

## Whitelist (regex)

`src/data/whitelist.yaml` contains regular expressions: an FQDN matching any of them is never scored (score 0, no rule executed). Regexes are case-insensitive and applied with `re.search`: anchor them with `^` and `$`.

```yaml
patterns:
- '(^|\.)(admin-)?(rs-)?mcas(-df)?\.ms$'
```

An invalid regex aborts startup with a message naming the faulty pattern. Another file can be supplied with `--whitelist path.yaml`.

The whitelist is global. For an official brand domain, prefer adding the domain to `src/data/brands_legits_domain.yaml`, then re-run `python scripts/generate_typosquats.py` to also exclude its TLD variants.
